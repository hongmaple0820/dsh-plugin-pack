# 09 · 信息架构与交互设计（UI/UX）

> 回答的问题：**「上面一排菜单很混乱割裂、布局交互不标准、不能选项目、新建/编辑流水线很奇怪。」**
> 结论：根因不是配色或间距，而是**没有信息架构**——13 个同权重控件平铺在一个工具条里，7 个是「整页 view 开关」，没有路由、没有深链，项目选择退化成下拉框。

---

## 1. 现状诊断（有代码证据）

| 现象 | 证据 | 后果 |
|---|---|---|
| 13+ 个同权重控件一行平铺 | `client.js:2069–2201`：项目/目标/构建机 3 个 select + 计划/干跑/运行/发布/审计/编辑/新建/审批/RBAC/Secrets/Runner/通知/刷新 | 用户每次都要扫全表找按钮；危险操作与只读操作视觉同权 |
| 7 个「整页 view」开关 | `view ∈ {audit, releases, editor, create, approvals, rbac, secrets, runners}` | 进入后无法保留上下文，返回即丢失滚动与筛选；文案在「打开」/「返回运行视图」间来回变 |
| 零路由 | `client.js` 全文无 `location/history/pushState` | 刷新回到默认视图；不能分享「这次失败的 run」链接；浏览器后退失效 |
| 项目选择是 `<select>`（`client.js:2073`），单项目时退化为静态文本 | — | 无法搜索、无法看最近访问、无法从 URL 直达 |
| 目标/构建机也各占一个 select | `2091`、`2102` | 「选项目 → 选环境 → 选构建机」三个同级下拉，实际是三层不同语义的上下文 |
| 没有总览 | — | 「今天哪些失败了」「prod 现在跑的哪个版本」要跨页面拼 |

**这不是「再补几个页签」能解决的**——页签作为一级导航，天然答不了跨项目的问题，且每多一层就多一次跳转。

---

## 2. 信息架构

### 2.1 两层导航：全局侧栏 + 项目上下文

```
┌──────────────────────────────────────────────────────────────────────┐
│  DSH · CI/CD        [⌘K 搜索]                    [通知] [头像/角色]  │
├───────────────┬──────────────────────────────────────────────────────┤
│ ▾ 全局        │                                                      │
│  ▸ 项目       │                                                      │
│  ▸ 运行       │              内  容  区                              │
│  ▸ 环境       │                                                      │
│  ▸ 制品       │                                                      │
│  ▸ 构建机     │                                                      │
│  ▸ 审计       │                                                      │
│  ▸ 设置       │                                                      │
│               │                                                      │
│ ▾ 当前项目    │                                                      │
│  shop-api ▾   │                                                      │
│  ▸ 概览       │                                                      │
│  ▸ 流水线     │                                                      │
│  ▸ 环境       │                                                      │
│  ▸ 制品       │                                                      │
│  ▸ 计划与触发 │                                                      │
│  ▸ 设置       │                                                      │
└───────────────┴──────────────────────────────────────────────────────┘
```

**为什么不是项目内页签**：NN/g 的导航研究结论是「一级导航只应有一行、层级不超过两层」；项目内页签在切项目时会全部重建，且无法表达「跨项目的运行列表」。侧栏 + 上下文是 GitHub/GitLab/Vercel 的共同选择。

### 2.2 路由（可分享、可刷新、可后退）

```
/                                  → 重定向到 /projects
/projects                          → 项目列表
/projects/:project                 → 项目概览
/projects/:project/pipelines       → 流水线列表
/projects/:project/pipelines/:pipe → 流水线详情（最近运行 + 配置摘要）
/projects/:project/pipelines/:pipe/edit  → 编辑器
/projects/:project/runs            → 运行列表（可按状态/分支/触发者筛）
/projects/:project/runs/:runId     → 运行详情（含日志、制品、审批）
/projects/:project/envs/:env       → 环境详情（当前版本、实例、回滚）
/projects/:project/artifacts       → 制品
/projects/:project/schedules       → 计划与触发
/projects/:project/settings        → 项目设置（成员/保护规则/webhook）
/runners  /audit  /settings        → 全局
```

- 用 hash 路由（`#/projects/...`）即可，无需服务端 rewrite；刷新、深链、后退全部成立。
- **所有列表筛选进 URL query**：`?status=failed&branch=main&page=2`。

### 2.3 项目选择（用户最直接的抱怨）

- 顶栏左侧是**项目切换器**：点击展开，含搜索框、最近访问、收藏、`+ 新建项目`。
- 快捷键 `⌘K / Ctrl+K` 打开命令面板：跳项目、跳运行、执行动作（「部署 shop-api 到 staging」）。
- 单项目时**不隐藏**切换器（否则用户以为系统只能有一个项目），只显示「1 个项目」+ 新建入口。

- 阶段条（≤10 个 job 足够）而不是实时 DAG 动画。

- 日志面板固定高度、虚拟滚动、可折叠、可下载原文。

### 3.3 新建 / 编辑流水线（用户说「很奇怪」的地方）

现状：整页替换三栏，只有一个 textarea + 保存按钮，模板靠 `kind` 下拉，保存前看不到将执行什么。

改为**三栏 + 双模式**：

```
┌ 模板 ─────────┐ ┌ 配置 ──────────────────┐ ┌ 预览 ──────────────┐
│ 推荐（自动识别）│ │ [表单] [YAML]          │ │ 将执行：            │
│ · Node 20     │ │ ┌────────────────────┐ │ │ 1. checkout        │
│ · Java 17+Mvn │ │ │ stages:            │ │ │ 2. toolchain java17│
│ · PHP 8.3     │ │ │   - id: build      │ │ │ 3. mvn -B package  │
│ · Python 3.11 │ │ │     jobs: [...]    │ │ │ 4. deploy → staging│
│ · Go 1.22     │ │ └────────────────────┘ │ │ 校验：✓ 通过        │
│ · Docker      │ │ 行内错误 + 文档链接     │ │ 目标：staging(2 台) │
│ · 空白        │ │                        │ │                    │
└───────────────┘ └────────────────────────┘ └────────────────────┘
                                                   [取消] [保存并运行]
```

- **表单模式**覆盖 80% 场景（选语言/版本/目标/命令），YAML 模式给高级用户；两者双向同步，切换不丢内容。
- 保存前必须跑 `validate` 并显示**插值后的真实命令**（现在只有 `cicd_plan` 工具能给，UI 没暴露）。
- 模板列表来自后端 `templates/` 目录（见 04），支持自定义模板与「另存为模板」。
- 保存时展示 diff（旧 vs 新）并写 `pipeline.config_changed` 审计。

### 3.5 首次引导（3 步，5 分钟内闭环）

| 步骤 | 做什么 | 验收 |
|---|---|---|
| ① 接入仓库 | 选本地目录或 Git URL；自动识别技术栈，生成 pipe.yml，**当场校验通过**；也可手选模板 | 用户看到「配置已就绪」，一条命令都没跑 |
| ② Run on dev | 一键运行，实时日志；失败钉首个错误行 + `file:line` + 修复建议 | 5 分钟内出结果（成功或明确可行动的失败） |
| ③ 部署 staging | 演示护栏：看到被哪条规则拦、批准、环境页出现版本、可回滚、审计有记录 | prod 仍锁定，用户理解「为什么锁」 |

## 4. 设计系统（最小集）

**间距**：4 的倍数（4/8/12/16/24/32）。**圆角**：4（控件）/8（卡片）。**字号**：12 辅助 / 13 正文紧凑 / 14 正文 / 18 区块标题 / 24 页面标题。

**语义色**（不自定义品牌色板，沿用 IDE/DSH 主题变量）：

| 语义 | 用途 |
|---|---|
| success | 成功、健康 |
| danger | 失败、危险操作、prod 保护 |
| warning | 降级、等待审批、超时 |
| info | 进行中、提示 |
| muted | 次要文本、禁用 |

**状态必须「色 + 图标 + 文字」三重编码**（色盲可辨）。

**交互规则：**

1. **只在不可逆/高代价操作上确认**：部署 prod、回滚、删除项目。其余用「可撤销」：乐观更新 + 5s 内撤销 toast。
2. **按钮层级**：每屏一个 primary；危险操作永远不与 primary 相邻。
3. **键盘**：`⌘K` 命令面板、`g p` 跳项目、`g r` 跳运行、`?` 快捷键帮助、`Esc` 关闭。
4. **加载**：骨架屏（不是 spinner 转圈）；超过 400ms 才显示。
5. **空状态**：一句话说明 + 一个主行动 + 一个文档链接（不要只画插画）。
6. **错误**：人话 + 错误码 + 「复制诊断信息」+ 下一步链接。
7. **不做**：实时 DAG 动画、力导向图、嵌套多行页签、无限日志不虚拟化。

**可访问性**：焦点可见、`aria-live` 播报运行状态、日志区可键盘滚动、对比度 ≥ 4.5:1。

**响应式**：<960px 侧栏折叠为图标；<720px 三栏降为单栏 + 顶部切换。

## 5. 日志查看器规范

| 能力 | 要求 |
|---|---|
| 跟随 | 默认跟随；用户上滚即暂停；出现「回到底部」按钮 |
| 搜索 | 实时高亮、命中计数、`Enter`/`Shift+Enter` 跳转 |
| 折叠 | 按 stage/step 折叠；折叠时显示末行与状态 |
| ANSI | 支持颜色，但 `danger` 语义色优先 |
| 脱敏 | 服务端已脱敏，前端不再二次处理 |
| 下载 | 原始 `.log`（已脱敏） |
| 性能 | 虚拟滚动；10 万行不卡；增量拉取（`/log-ws` 已有） |
| 深链 | `#/runs/:id?step=deploy&line=1204` 定位到行 |

## 7. 验收标准

1. 刷新任意页面不丢失视图；复制 URL 发给同事能打开同一运行、同一行日志。
2. 从「项目 A 的运行」切到「项目 B 的环境」≤2 次点击，且项目切换器可搜索。
3. 新建流水线：选模板 → 看到插值后命令 → 校验错误定位到行 → 保存并运行，全程不离开当前页。
4. 运行失败时，首屏能直接看到首个错误行与修复建议，不需要展开日志。
5. 键盘可达：不摸鼠标完成「切项目 → 找到失败运行 → 重跑」。
6. 1300px 与 800px 宽度下均无横向滚动条；侧栏可折叠。
7. 危险操作（部署 prod / 回滚 / 删除）都有确认且文案说明影响范围；可逆操作无确认。
